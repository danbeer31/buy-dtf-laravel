# Required technical approach

## 1. Use existing cart/order system
Do not create a second cart or second order path.

Gang sheets should be represented as a new item mode/type/branch within the existing data model and cart flow.

## 2. Centralize pricing
Create a dedicated pricing service for gang sheets.

Do not spread pricing logic across:
- controllers
- blade/views
- JS
- duplicated helper code

Qty changes must reprice correctly, especially for 22x96 tiers.

## 3. Keep checkout pipeline unchanged
Do not alter the core checkout/payment pipeline beyond what is needed to support gang sheet line-item metadata and pricing.

Be extra careful not to disrupt:
- Stripe flow
- QBO invoice/accounting behavior
- existing order creation
- tax/shipping/discount assumptions

## 4. Reuse existing storage/upload patterns
Uploads must use the project’s existing storage conventions where possible.

Add strict server-side validation for:
- MIME
- extension
- file size

Do not rely on extension only.

## 5. Admin/production should be read-only extensions first
Add gang sheet visibility into admin/production in a conservative way first:
- badge/type label
- selected size
- qty
- file link
- notes

Do not over-automate phase 1 if it adds risk.
